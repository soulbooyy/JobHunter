## SL-02.M2 Demanded preview and export

**Goal/value:** Turn exact formal Resume versions into demanded PDF/PNG material independently of Save success.

**Scope:** Explicit exact-version RenderIntent, immutable application-delivered RenderConfiguration, contained provenance Manifest, published Artifact, atomic receipt/Intent/Artifact-or-Work selection, safe local execution/recovery, fenced publication and pure metadata/content reads. PDF is multi-page A4; PNG concatenates all matching A4 pages into one long image. Shared Work and Artifact reuse preserve independent Intent and Artifact identities. [CG04-Q1–Q135](../../design/contract/sl-02-m2-grill.md) supersedes this plan's former unselected MaterialBundle/follow-current/obsolete-target suggestions for M2.

**Out of scope:** MaterialBundle, CURRENT_RESUME subscriptions, automatic Save-triggered demand, cancel/release, force-rerender, public history/Work/repair APIs, user configuration CRUD, Preparation approval/Greeting/send authorization and model/platform replay. Editor-local Draft preview remains M1 frontend scope.

**Required upstream capability:** The implemented M1 saved-authority backend: exact Resume/Profile and typed Evidence data, durable command/persistence/access infrastructure. M1 full Candidate readers are available but are not substitutes for the new Materials-specific Evidence projection. M1 frontend completion is not a backend prerequisite; integrated UI remains separate.

**Required Contract portions before development:** COM-043–046, WSP-012, PRO-009, EVD-015, RES-016, SAV-017, MAT-004–030, DRW-001–026 and STO-029–039 at 2026-09-21.S2M2-r1, together with their explicitly referenced M1/shared clauses. Read current [readiness and interface evidence](../../progress/traceability.md#64-sl-02m2-reviewed-scope-and-interface-evidence), not filename-level readiness.

**Joint agreement:** Materials owns sources/configuration/output; Derived Work owns intent/execution; Storage owns durable relationships/files. Acceptance commits receipt + Intent + verified Artifact binding, unfinished Work association or new Work/association in one transaction. Candidate Save has no new participant in this exact-only scope; its future actual-demand atomicity invariant is preserved by SAV-017. The internal source producer/consumer interface excludes unused Evidence expression without weakening full Candidate GET/Save. New demand eligibility and accepted historical execution are distinct.

**Research/development entry:** Use the [SL-02.M2 backend handoff](../../development/handoff/sl-02-m2-handoff.md). Concrete catalog, exact font hashes/rights, pipeline versions, layout parameters, operational limits and filesystem behavior require engineering evidence. The scoped Source Han Sans italic exception is permitted but unverified; all four fonts/roles and required outputs must pass their capability gates. Recheck actual migration head; add a forward migration without fixing schema 4 in business norms. No renderer, migration or implementation is delivered by Contract publication.

**Implementation sequence:** Verify upstream and engineering prerequisites; implement owned domain/source projection and versioned persistence; implement acceptance/receipts/read APIs; establish and verify the fixed renderer/catalog; integrate Coordinator/discovery/fencing/recovery and managed file serving; reconcile OpenAPI/API consumer documentation and then frontend integration. Dependent work cannot claim readiness from an unverified rendering stack.

**Tests / Eval:** [Acceptance §4.3](../../acceptance.md#43-demand-and-safe-derivative-recovery), V9.3/V10 and DRW-026 cover three acceptance branches, concurrency, unknown commits, historical/remove behavior, projection integrity, restart/counts, timeouts/live writers, file publication and actual PDF/PNG/client proof. This deterministic milestone has no model Eval consumer.

**Milestone completion:** Actual backend and frontend consumers produce/read correctly bound usable artifacts with the required failure/concurrency/recovery proof. Record Contract review, upstream capability, code delivery and acceptance separately; parent SL-02 remains incomplete while M1 frontend or M2 implementation/integration is unfinished.
