## SL-10.M1 Ordinary Preparation and viewed-material approval

**Scope:** Single/multi-Job independent Preparation, idempotent create/reentry, source selection and revisions, actual rendered material view, fixed generic Greeting, exact viewed-material approval and snapshot. No body editing, generated personalized Greeting or external send.

**Upstream:** Actual formal Job producer and SL-02.M2 exact materials over schema-2 Resume. Reuse scoped persistence/runtime where needed. No Advisor, DeepFit or portrait-readiness dependency.

**Required scope/blockers:** MAT-031–033/RES-024 source interface is reviewed; planned preparation and execution-facing snapshot/approval Contracts must still define their own complete protocol. Old Profile/Evidence binding eligibility and joins are removed.

**Backend/frontend:** First implementation. Select any ACTIVE independent Resume; bind exact artifact/version and actual viewed Greeting. UI must show actual bytes and changed-input/reconfirmation states; default switch/portrait refresh cannot retarget selection, view, approval or frozen snapshot.

**Proof/completion:** Duplicate/reentry/revision conflicts, actual view versus metadata, missing/changed materials, permission revocation, default/portrait change during approval, independent batch outcomes and absence of send authority. Ordinary Preparation requires neither optimizer nor adopt-back.

**Development entry:** [SL-10.M1 handoff](../../development/handoff/sl-10-m1-handoff.md). Reverify actual code and commands; do not infer implementation from this plan.
