# SL-03.M1 API — Invocation durability and recovery

This guide describes the implemented **internal Python API** for controlled Run/Invocation consumers. There are no new HTTP routes, OpenAPI schemas, frontend clients or pages. It follows the API-guide convention for operations, values and integration obligations; it is not a new normative Contract.

The baseline is **2026-09-23.S3M1-r1**: [Execution Runtime](../contracts/agent/execution-runtime.md) EXR-001–034, [Common](../contracts/common.md#com-047) COM-047–048, [Storage](../contracts/foundation/storage.md#sto-040) STO-040–045 and [deterministic evidence](../contracts/evaluation/evaluation-observability.md) EVO-001–007, including their shared [Workspace](../contracts/foundation/workspace.md) obligations. Contracts own semantics; [Progress](../progress.md) and the [requirement-to-code/test mapping](../progress/traceability.md#invocation-backend-evidence) own status and executed proof.

## Availability and composition

Use the existing installation, launcher and explicit offline migration commands in [backend/README.md](../../backend/README.md). The current schema is **5**, with forward revision `d092ea64bf17` after `a41d7e90c263`. Existing databases are not silently migrated; migration preserves prior data and receipts without inventing historical Runs or Invocations.

[Bootstrap](../../backend/src/jobhunter/bootstrap/invocation.py) composes `invocation_runtime(store, *, clock=None, consumers=None, formats=None)`. It returns a started [Runtime](../../backend/src/jobhunter/agent/harness/runtime.py), registers it on the Store and uses these defaults:

| Registration | Exact key | Purpose |
| --- | --- | --- |
| Model consumer | `controlled.model.v1` | Two-response local completion proof |
| Pure local-read consumer | `controlled.read.v1` | One exact-source TOOL result |
| Response format | `controlled.response.v1` | Fixed controlled JSON bytes |

Compose once per physically owned Store lifetime. The launcher already does this before readiness; application composition reuses that instance. Closing the Store invalidates access; a forked process cannot inherit execution authority. Runtime instance identity is a fresh UUIDv4. Duplicate registration or a second Runtime on the same Store is rejected. Repository and persistence ports are implementation seams, not alternative caller mutation APIs.

## Results and values

Except for `model_path`, operations below return the typed `Result[T]` union from [Domain models](../../backend/src/jobhunter/domain/invocation/models.py):

| Variant | Fields | Caller obligation |
| --- | --- | --- |
| `Success[T]` | `value` | Interpret this operation's value, not general Run completion |
| `Rejected` | `code` | Handle the explicit refusal; do not infer that every earlier write was absent |
| `Unresolved` | `code`, `identity: str \| None` | Retain any supplied identity; stop dependent work until authoritative reconciliation |

These are Python values, not JSON envelopes or HTTP status mappings. Bootstrap and `model_path` can raise the sanitized Domain `Failure` exception; handle those boundaries separately from Result-returning operations. In particular, `Success(None)` from recovery/ending coordination is not a completed Run. A durable response is not whole-Run success. Failures and diagnostics must not include business payloads, SQL parameters or raw adapter exceptions.

Domain projections are frozen, closed Pydantic models. Required nullable fields must be present when constructing them. IDs are canonical lowercase UUIDv4; keys are exact and case-sensitive, without trimming. Instants use `YYYY-MM-DDTHH:mm:ss.sssZ`. Generations are exact nonnegative safe integers; a qualification requires a positive generation. Booleans and fractional values are not integers. Captured byte limits are positive exact integers and are not restricted to SQLite's signed 64-bit range.

| Projection | Fields |
| --- | --- |
| `Run` | `run_id`, `consumer_key`, `run_status`, `execution_generation`, `owner_runtime_instance_id`, `deadline_at`, `created_at`, `ended_at`, `end_reason`, `failure_code` |
| `Qualification` | `run_id`, `runtime_instance_id`, `execution_generation` |
| `Ending` | `run_id`, `execution_generation`, `ended_at`, `end_reason`, `failure_code` |
| `ModelInvocation` | `invocation_id`, `run_id`, `kind="MODEL"`, `response_format_key`, `max_response_bytes`, `durability_phase`, `dispatch_generation`, `response_rejection_code` |
| `ModelRead` | `invocation: ModelInvocation`, `descriptor: Descriptor \| None` |
| `Descriptor` | `target="controlled.echo.v1"`, `text`, `ordinal` |
| `Publication` | `invocation_id`, `response_format_key`, `sha256`, `byte_length` |
| `Response` | All Publication fields plus `serialized_payload: bytes` |
| `LocalRead` | `invocation_id`, `run_id`, `kind="TOOL"`, `action_key`, `source_invocation_id`, `lineage_id`, `result_sha256`, `result_byte_length` |

A Run is `OPEN` or `ENDED`. Ending reasons are `COMPLETED`, `FAILED`, `CANCELLED`, `TIMED_OUT`, `OUTCOME_UNKNOWN`; `failure_code` is populated only for `FAILED`. MODEL durability phases are `PREPARED`, `DISPATCH_INTENT_DURABLE`, `RESPONSE_DURABLE`. TOOL results have no MODEL durability phase or dispatch generation. Optional lineage is audit-only and is not a dependency to follow.

## Operations

The tables show Python argument names and the type inside `Success.value`. Pass values returned by the Runtime rather than reconstructing execution authority from stored rows.

### Run ownership and ending

| Operation | Success value | Meaning |
| --- | --- | --- |
| `create_run(consumer_key, deadline_at)` | Run ID | Creates an ownerless OPEN Run at generation 0; nullable deadline does not grant unlimited execution |
| `read_run(run_id)` | `Run` | Reads durable state without advancing it |
| `establish_deadline(run_id, deadline_at)` | Exact instant | Establishes once; equal value confirms, different value is frozen |
| `grant_execution(run_id, expected_generation)` | `Qualification` | Admits the current runtime and increments generation exactly once |
| `revoke_execution(qualification)` | Retained generation | Clears current ownership without incrementing generation |
| `cancel_run(run_id)` | `Ending` | Run-wide durable cancellation and logical fencing of siblings |
| `end_run(qualification, end_reason, failure_code=None)` | `Ending` | Current executor may request confirmed `COMPLETED` or elapsed `TIMED_OUT`; it cannot set arbitrary failure facts |
| `coordinate_ending(run_id, expected_generation)` | `Ending \| None` | Derives completion/failure facts for an ownerless Run at the expected generation |
| `recover_run(run_id)` | `Ending \| None` | Reconciles, admits bounded local recovery and coordinates ending; does not replay remote calls |
| `startup()` | List of per-Run `Result[Ending \| None]` | Fences former owners and reconciles OPEN Runs; bootstrap calls this once |

Existing endings remain immutable. An outer successful startup result does not mean every per-Run result succeeded. Unknown affected operations remain stopped. The factory checks startup's outer result; inspect retained Run state when diagnosing an individual recovery outcome.

### MODEL dispatch and response

| Operation | Success value | Meaning |
| --- | --- | --- |
| `prepare_model_invocation(qualification, response_format_key, max_response_bytes)` | Invocation ID | Captures format and full-response byte limit |
| `read_model_invocation(invocation_id)` | `ModelRead` | Reads phase and any committed descriptor |
| `model_path(invocation_id, qualification)` | Context manager yielding `None` | Establishes the unique live sending context; not a Result or transferable token |
| `commit_dispatch_intent(invocation_id, qualification, descriptor)` | `None` | Atomically publishes exact descriptor and original dispatch generation |
| `send(invocation_id, qualification, gateway)` | `Publication` | Enters the controlled adapter at most once and publishes a complete response |
| `publish_response(invocation_id, qualification, serialized_payload)` | `Publication` | First publication needs the original entered sending path; existing equal response is read-only confirmation |
| `read_response(invocation_id)` | `Response` | Reads and verifies actual stored bytes, digest and length without mutation |

Keep intent and `send` in the **same** `model_path` context, on the same thread/task. Authority equality in storage does not prove that a path won dispatch. Exiting the context, losing the path, crashing or taking over cannot create a replacement sender for an existing intent. No adapter retry or fallback is allowed.

First publication derives the format from the Invocation and the hash/length from actual bytes. It requires current authority, original dispatch generation/path and an unexpired deadline. The existing-response-first branch verifies retained bytes and association, returns the original Publication for identical bytes and rejects different bytes. It performs no write, decoder invocation or Run repair, including after ending or expiry. Raw response reads likewise cannot repair or end a Run.

### Controlled pure local read

| Operation | Success value | Meaning |
| --- | --- | --- |
| `prepare_local_read(qualification, source_invocation_id, lineage_id=None)` | TOOL Invocation ID | Acquires an exact already-durable MODEL source before the original deadline |
| `resume_local_read(invocation_id, qualification)` | `LocalRead` | Verifies local source bytes and commits digest/length, or reuses a valid retained result |

The same unfinished TOOL Invocation may resume under a fresh valid qualification after recovery. It does not create a replacement Invocation, resolve a newer source, run Ensure, call a provider or write business authority.

## Controlled agreements and response bytes

The [controlled consumer](../../backend/src/jobhunter/application/invocation/controlled.py) is a proof consumer, not a general business DTO or future permission policy:

- `controlled.model.v1` admits at most two MODEL Invocations and no TOOL. Completion requires exactly two valid durable responses and its committed local proof. A single response cannot complete the Run.
- `controlled.read.v1` admits no MODEL and one `controlled.response-read.v1` TOOL. Its exact input is the retained source Invocation ID; output is verified SHA-256 and byte length. Valid committed results can be reused without rereading unnecessary source payloads.
- Permission callbacks return `ALLOW`, `DENY` or `UNRESOLVED`. Denial maps to `CONTROLLED_PERMISSION_DENIED`; unavailable exact source maps to `CONTROLLED_SOURCE_UNAVAILABLE`; unknown action maps to `CONTROLLED_ACTION_UNAVAILABLE`. Corruption remains an integrity failure. Unknown dependency/permission outcomes remain unresolved.
- Both require an established deadline. New remote work, new acquisitions and first response publication stop at that deadline. Eligible local recovery ends at the original deadline plus **30 seconds**, without renewal on restart. Live elapsed time also supplies a monotonic floor. Completion reconciliation runs before recovery admission.

[ControlledResponse](../../backend/src/jobhunter/domain/invocation/format.py) serializes `terminal`, `text`, `ordinal` in that fixed order, with compact UTF-8 JSON, normal JSON escaping, scalar Unicode and an exact nonnegative safe integer ordinal. No Unicode normalization, ASCII escaping, BOM or trailing newline is added. Decoding requires those same canonical bytes; alternative key order, duplicate/extra fields and alternative numeric spellings are not accepted.

```text
{"terminal":"STOP","text":"proof","ordinal":0}
```

Both `STOP` and `LIMIT` represent complete protocol termination. `Frame.terminal` separately establishes that the complete byte stream has arrived. A transport interruption is not a `LIMIT` response.

The [Gateway port](../../backend/src/jobhunter/application/invocation/ports.py) exposes `receive(descriptor, receive_limit) -> Iterable[Frame]` and best-effort `interrupt()`. Runtime bounds reception to `2 * max_response_bytes + 256` bytes and admits at most `max_response_bytes + 1` frames, rechecking authority/deadline between frames. The adapter must provide finite frames and must not hide retry/fallback. Complete oversized output within reception bounds atomically records `RESPONSE_TOO_LARGE` and Run failure, without retaining the body or advancing to RESPONSE_DURABLE. A cutoff or interrupted stream without complete terminal evidence remains an unknown remote outcome.

## Executable local example

Run this Python 3.12 example with `UV_CACHE_DIR=/tmp/jobhunter-uv-cache uv run --locked python /path/to/example.py` from the repository root. It uses a new temporary Workspace, no user database and no network. The helper deliberately stops on every non-success; it is not an automatic recovery/retry policy.

```python
from collections.abc import Iterable
from datetime import UTC, datetime, timedelta
from pathlib import Path
from tempfile import TemporaryDirectory

from jobhunter.application.invocation.ports import Frame
from jobhunter.bootstrap.invocation import invocation_runtime
from jobhunter.domain.invocation.format import FORMAT_KEY, ControlledResponse
from jobhunter.domain.invocation.models import Descriptor, Result, Success
from jobhunter.infrastructure.persistence.sqlalchemy.uow.store import Store


def require[T](result: Result[T]) -> T:
    if not isinstance(result, Success):
        raise RuntimeError(result.code)
    return result.value


class EchoGateway:
    def __init__(self) -> None:
        self.calls = 0

    def receive(self, descriptor: Descriptor, receive_limit: int) -> Iterable[Frame]:
        self.calls += 1
        payload = ControlledResponse(
            terminal="STOP", text=descriptor.text, ordinal=descriptor.ordinal
        ).serialize()
        assert len(payload) <= receive_limit
        yield Frame(data=payload, terminal=True)

    def interrupt(self) -> None:
        pass


with TemporaryDirectory(prefix="jobhunter-invocation-guide-") as directory:
    with Store.open(Path(directory)) as store:
        runtime = invocation_runtime(store)
        deadline = (datetime.now(UTC) + timedelta(minutes=1)).isoformat(
            timespec="milliseconds"
        ).replace("+00:00", "Z")
        run_id = require(runtime.create_run("controlled.model.v1", deadline))
        grant = require(runtime.grant_execution(run_id, 0))
        gateway = EchoGateway()
        sources: list[str] = []
        for ordinal in range(2):
            invocation_id = require(runtime.prepare_model_invocation(grant, FORMAT_KEY, 4096))
            descriptor = Descriptor(target="controlled.echo.v1", text="proof", ordinal=ordinal)
            with runtime.model_path(invocation_id, grant):
                require(runtime.commit_dispatch_intent(invocation_id, grant, descriptor))
                require(runtime.send(invocation_id, grant, gateway))
            sources.append(invocation_id)
        assert gateway.calls == 2
        require(runtime.revoke_execution(grant))
        ending = require(runtime.recover_run(run_id))
        assert ending is not None and ending.end_reason == "COMPLETED"

        read_run = require(runtime.create_run("controlled.read.v1", deadline))
        read_grant = require(runtime.grant_execution(read_run, 0))
        tool_id = require(runtime.prepare_local_read(read_grant, sources[0]))
        result = require(runtime.resume_local_read(tool_id, read_grant))
        response = require(runtime.read_response(sources[0]))
        assert result.result_sha256 == response.sha256
        assert result.result_byte_length == response.byte_length
        assert require(runtime.end_run(read_grant, "COMPLETED")).end_reason == "COMPLETED"
        confirmation = require(runtime.publish_response(sources[0], grant, response.serialized_payload))
        assert confirmation.sha256 == response.sha256
        assert gateway.calls == 2
print("Controlled model, local read and historical confirmation passed")
```

## Failure and recovery obligations

| Condition / representative code | Integration behavior |
| --- | --- |
| `INVALID_INPUT`, `REFERENCE_MISMATCH` | Correct the caller's closed values or association; do not reinterpret IDs |
| `EXECUTION_NOT_CURRENT`, `SENDING_PATH_UNAVAILABLE` | Stop that execution path; stored matching authority cannot replace lost live sending rights |
| `DEADLINE_FROZEN`, `DEADLINE_NOT_EXPIRED`, `COMPLETION_NOT_CONFIRMED`, `ENDING_NOT_AUTHORIZED` | Respect fixed time and owned completion/ending evidence |
| `RESPONSE_FORMAT_UNAVAILABLE`, `RESPONSE_FORMAT_INVALID` | Do not substitute another reader/version or claim semantic success |
| `RESPONSE_PAYLOAD_UNAVAILABLE`, `RESPONSE_INTEGRITY_FAILED`, `INTEGRITY_CONFLICT` | Distinguish missing payload, corrupted retained evidence and unequal publication; reads do not repair state |
| `RESPONSE_TOO_LARGE` | Complete oversize rejection is durable evidence, not an available saved response |
| `REMOTE_OUTCOME_UNKNOWN` | A remote result was not safely published; inspect durable ending and never automatically resend |
| `OUTCOME_UNKNOWN` | A local write may have committed; retain identity and reconcile, never automatically replay the command or adapter call |
| `STORAGE_UNAVAILABLE`, `CONSUMER_UNRESOLVED` | Do not treat unavailable/unknown evidence as absence, denial or permission to proceed |
| `CONSUMER_UNAVAILABLE` | Missing historical consumer is scoped to its affected Run; do not substitute a different consumer |

These codes span operation refusals and owned terminal failure evidence; always inspect the Result variant and durable Run separately. The table is an integration guide, not a new universal error enum.

An uncertain write receives one fresh authoritative read internally; neither the command nor COMMIT is retried. Only the original live path may reconcile its dispatch acknowledgement and continue if its own winning evidence remains valid. Crash/takeover recovery cannot replay that dispatch, even if the provider was never reached. Startup fences old owners without increasing generation; only a successful grant increases it. Cancellation/ending fence every sibling Invocation and late callback. Physical interruption is best effort and does not fabricate response evidence or refund usage.

## Boundaries and verification

This interface does not provide production Provider/SDK integration, full Skill/Context/Tool/Budget admission, RequirementParse/Ensure, semantic quality Eval, remote side effects, business writes, generic retry/lineage commands or an observability platform. Materials keeps its separate queue, attempt and renderer fencing. M1 completion does not establish M2/M3 or parent SL-03 completion.

The maintained full check is `UV_CACHE_DIR=/tmp/jobhunter-uv-cache ./scripts/check`. Actual deterministic Application/SQLite/process/adapter tests and migration/consumer regressions are linked in the [Invocation evidence ledger](../progress/traceability.md#invocation-backend-evidence). This guide's example demonstrates internal composition only; it is not production provider or frontend acceptance.
