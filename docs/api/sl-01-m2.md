## Access and operations

Default base URL is `http://127.0.0.1:8765`. Host must match the explicit allowlist, including port. Browser Origin is denied unless explicitly configured with `JOBHUNTER_ALLOWED_ORIGINS`; no wildcard. Use `application/json` (optionally `charset=utf-8`) and no Content-Encoding or `identity`. OpenAPI is generated at `/openapi.json` under the same access boundary. Setup, startup and explicit schema-1 migration commands are maintained in the backend README.

| Method / path | Input | HTTP 200 result |
| --- | --- | --- |
| GET `/api/v1/preferences` | No body or query parameters | Current state, below |
| POST `/api/v1/preferences/save` | Complete Save object, below | Original successful request's IDs/revision/outcome |
| GET `/api/v1/preferences/versions/{preference_set_version_id}` | Lowercase UUIDv4; no body/query | Complete exact immutable version |

There is no PATCH, delete, reset, history-list or restore endpoint. Preferences express future Collection intent; they do not filter saved formal Jobs, start Collection or affect manual application entries.

## Complete Save

```json
{
  "request_id": "11111111-1111-4111-8111-111111111111",
  "revision": null,
  "configuration": {
    "target_job_keywords": ["Python", "工程师"],
    "accepted_cities": {"mode": "LIMITED", "value": ["北京", "深圳"]},
    "minimum_salary": {"mode": "LIMITED", "value": 15000},
    "recruitment_types": {"mode": "LIMITED", "value": ["CAMPUS", "INTERNSHIP"]},
    "excluded_companies": {"mode": "UNLIMITED"},
    "max_required_education": {"mode": "LIMITED", "value": "BACHELOR"}
  }
}
```

All three request fields and all six configuration fields are required. `revision: null` asserts that no root exists; otherwise send the revision last read. Missing or zero revision does not mean first Save. Generate a new UUIDv4 for a new logical Save; retain the original full request for explicit retry after uncertainty. System IDs/timestamps and unknown fields are forbidden.

Each of the five choice fields is either exactly `{"mode":"UNLIMITED"}` or exactly `{"mode":"LIMITED","value":...}`. An UNLIMITED choice must omit value, including null/empty values. Keywords always need a nonempty array.

| Field | LIMITED / canonical value | Input/design considerations |
| --- | --- | --- |
| target_job_keywords | 1–20 strings, each 1–100 code points | Item input + Add/removable chips; commas remain literal |
| accepted_cities | 1–50 strings, each 1–100 code points | Item input + Add/removable chips; no inferred adjacent cities |
| minimum_salary | Exact integer 1–300000 | CNY pre-tax monthly base pay; excludes bonuses/equity/extra months; UI decimal digits only |
| recruitment_types | Nonempty set of CAMPUS, INTERNSHIP, EXPERIENCED, PART_TIME | Multiselect buttons; this order is canonical |
| excluded_companies | 1–200 strings, each 1–200 code points | Item input + Add/removable chips; exact names, no fuzzy matching |
| max_required_education | JUNIOR_HIGH_OR_BELOW, UPPER_SECONDARY, ASSOCIATE, BACHELOR, MASTER, DOCTORATE | Single-select dropdown; ceiling on Job requirements, not the user's own education |

Five independent UNLIMITED checkboxes disable their concrete controls. Blank/missing values are not implicit UNLIMITED. Backend text admission trims only Common's fixed outer whitespace, checks Unicode scalar legality and rejects remaining controls/separators. No case folding, Unicode normalization, internal-space collapsing or comma splitting occurs. Sets deduplicate exact admitted values; text sorts by Unicode code points, not JavaScript UTF-16 default order. Canonical order/duplicate-only changes are no-ops.

The transport accepts at most 1,048,576 actual UTF-8 body bytes and 1,000 raw items per multivalue array before deduplication. Every item is validated before deduplication; one invalid item rejects the whole Save. Integral JSON spellings such as `15000.0` or `1.5e4` are accepted without rounding, although the UI uses ordinary integer entry. Revision range is 1–9007199254740991. Duplicate decoded JSON object keys are rejected at every nesting level.

Example success:

```json
{
  "preference_set_id": "22222222-2222-4222-8222-222222222222",
  "preference_set_version_id": "33333333-3333-4333-8333-333333333333",
  "revision": 1,
  "outcome": "CREATED"
}
```

`CREATED` is first publication, `UPDATED` is a real canonical change, `UNCHANGED` is an admitted no-op. All return 200. Ordinary Save checks revision before equality. No-op at maximum revision succeeds; a change fails with REVISION_EXHAUSTED. A→B→A publishes a new A version. No-op/replay leaves business timestamps unchanged.

Matching successful request replay returns its original result after later Saves too. These returned IDs/revision do **not** prove it is still current. Read current separately when needed; failure of that read does not undo or reclassify Save success.

## Current and exact reads

Before first successful Save, current returns exactly:

```json
{"status":"NOT_CONFIGURED"}
```

After Save, current returns:

```json
{
  "status": "CONFIGURED",
  "preference_set": {
    "preference_set_id": "22222222-2222-4222-8222-222222222222",
    "current_preference_set_version_id": "33333333-3333-4333-8333-333333333333",
    "revision": 1,
    "created_at": "2026-09-20T01:00:00.000Z",
    "updated_at": "2026-09-20T01:00:00.000Z"
  },
  "current_preference_set_version": {
    "preference_set_version_id": "33333333-3333-4333-8333-333333333333",
    "preference_set_id": "22222222-2222-4222-8222-222222222222",
    "created_at": "2026-09-20T01:00:00.000Z",
    "configuration": {
      "target_job_keywords": ["Python", "工程师"],
      "accepted_cities": {"mode":"LIMITED","value":["北京","深圳"]},
      "minimum_salary": {"mode":"LIMITED","value":15000},
      "recruitment_types": {"mode":"LIMITED","value":["CAMPUS","INTERNSHIP"]},
      "excluded_companies": {"mode":"UNLIMITED"},
      "max_required_education": {"mode":"LIMITED","value":"BACHELOR"}
    }
  }
}
```

The exact-version endpoint returns the `current_preference_set_version`-shaped object directly, without status or another envelope. It can return a historical version and never substitutes current. Timestamps are UTC milliseconds; neither timestamp nor UUID provides a strict history order. The root's pointer selects current, and its revision orders modifications. Reads are side-effect-free and do not reserve state against later Saves.

## Errors and recovery presentation

All errors use the shared object. Example:

```json
{
  "code": "VALIDATION_ERROR",
  "message": "Validation error.",
  "field_errors": [
    {"field":"configuration.accepted_cities.value[1]","code":"BLANK_VALUE"}
  ]
}
```

Field paths reference known names and **original submitted indices**. Unknown keys map to the nearest known parent with UNKNOWN_FIELD and never echo the key. UNLIMITED with value produces INVALID_FORMAT at the choice parent. Field-error ordering or complete enumeration is not promised. Messages are sanitized human text; branch on codes, not message wording.

| HTTP | Codes / handling |
| --- | --- |
| 400 | BAD_REQUEST: malformed JSON, duplicate keys, invalid UTF-8 or unsupported transport |
| 403 | ACCESS_DENIED: Host/Origin rejected before business handling |
| 413 | REQUEST_TOO_LARGE: actual Save body exceeds 1 MiB |
| 422 | VALIDATION_ERROR: schema/value/path/query/body errors; show accurate field feedback |
| 404 | NOT_FOUND: well-formed exact version ID absent |
| 409 | REVISION_CONFLICT, REQUEST_CONFLICT, REVISION_EXHAUSTED; do not silently change precondition or request identity |
| 503 | STORAGE_UNAVAILABLE (read unavailable or confirmed Save non-commit), OUTCOME_UNKNOWN (verification required) |
| 500 | INTERNAL_ERROR; does not prove rollback |

Field codes: REQUIRED, UNKNOWN_FIELD, INVALID_TYPE, BLANK_VALUE, TOO_LONG, INVALID_CHARACTERS, INVALID_FORMAT, OUT_OF_RANGE. Examples and generated schemas remain subordinate to COM-033–037 and PRF-020.

Timeout, lost response, ambiguous write 5xx or an unrecognized response requires verification. Preserve the original request ID, revision and configuration for explicit retry. Current content equality does not prove success; different current content does not prove failure. A later definite 4xx does not prove an earlier uncertain attempt never committed. There is no durable browser retry queue or unsaved-draft crash recovery in this scope. Never represent OUTCOME_UNKNOWN as saved Preference state.
