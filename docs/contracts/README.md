# Contracts Overview

[Global documentation index](../index.md) · [Contract Index](index.md) · [Contract Structure](structure.md)

## Directory purpose

This directory contains navigation, a document-structure guide, five actual normative bodies covering SL-01.M1 and the consumed SL-01.M2 scopes, and planned later Contract destinations. Use Contract Index to find planned versus existing documents; use Contract Structure for the agreed file decomposition, family mapping, assigned definition destinations, references and later Grill boundaries.

Shared conventions stay in root `common.md`; domain documents are grouped under `foundation/`, `candidate/`, `jobs/`, `applications/`, `agent/` and `evaluation/`. The [directory layout](structure.md#directory-layout) and [Contract-to-milestone mapping](structure.md#6-milestone-consumption-and-progressive-readiness) remain maintained in Structure. Grouping changes paths, not business ownership or scope readiness. Development handoffs are separate under `docs/development/handoff/`.

## Authority boundary

README and index are navigation aids. Contract Structure is a non-normative organization plan subordinate to [Product](../spec.md) and [Architecture](../architecture.md); it is not a new business or architecture authority. Only reviewed normative Contract bodies define detailed requirements within their recorded scope. The original [Contract Design Inventory](../design/contract/README.md) is a separate non-normative source checklist.

[Implementation Plan](../plans/implementation-plan.md) and its Slice documents own delivery scope/dependencies, [Acceptance](../acceptance.md) owns proof, [Development](../development.md) requires Contract-ready development, [Progress recording rules](../progress/README.md) owns readiness/status/evidence representation, and [Progress](../progress.md) owns actual state. This README points to those rules without redefining them.

## Progressive Contract work

Follow the selected milestone's actually consumed normative scope under [Development](../development.md#51-define-a-bounded-reviewable-capability) and the [scope-readiness record](../progress/traceability.md#6-contract-normative-scope-readiness-ledger). Completion of unrelated files/families is not inferred from one ready portion. Navigation or structure files do not establish readiness or implementation.

Detailed Grill/writeback follows the existing W7/user-review boundary. The catalog does not call for empty placeholders. Add actual normative document links to Contract Index when those bodies exist; keep their detailed organization in Structure and their volatile evidence in Progress.
